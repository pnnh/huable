# Feature Specification: 笔记目录（文件夹）管理

**Feature Branch**: `001-note-directories`

**Created**: 2026-08-02

**Status**: Draft

**Input**: User description: "当前项目是一个部署在Cloudflare Worker上的笔记管理应用。在开发环境操作本地sqlite和文件系统，在部署到生产环境时操作cloudflare d1数据库。当前已经实现了新增笔记功能。现在需要支持创建"目录"功能，在notes表新增mime_type字段，mime_type字段等于directory的视做是目录。笔记类型的mime_type类型为text/markdown。同时需要在notes表中增加parent_id字段代表某个笔记属于某个目录。当parent_id为空认为位于根目录。之后在/[lang]/console/notes笔记管理页面，新增笔记按钮左侧增加一个创建目录功能。点击弹框提示用户输入目录名称（必选）和描述信息（可选），点击确认后保存。需要注意，统计目录或文件（parent_id相同时）不允许重名。最后将/[lang]/console/images改造成按树形表格页面，支持点击目录条目最左侧三角图标展开下级，同时支持点击目录项传参进入子级列表页面。考虑到风格一致，parentId参数在URL中的显示需要与/en/console/notes/Cdc6ZFomke37Vz84fqNEm URL中笔记id的格式类似（是一种base58编码后的值）。为目录和笔记条目左侧显示图标，图标大小和列表字体大小接近。注意在列表页面点击三角图标展开目录显示子级内容时，需要实际上需要连三角箭头、图标和文件名称一起作为整体缩进。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 创建目录 (Priority: P1)

用户在笔记管理页面希望像文件系统一样，通过"目录"对笔记进行分组归类。用户点击"新建笔记"按钮左侧新增的"新建目录"入口，在弹出的对话框中输入目录名称（必填）和描述信息（可选），确认后目录被创建并出现在当前所在层级（根目录或某个已选定的父目录）。

**Why this priority**: 这是本次需求的基础能力，没有目录创建能力，后续的树形浏览功能无从谈起，是整个特性的最小可用单元。

**Independent Test**: 可独立测试——在笔记管理页面点击"新建目录"，输入名称并保存，验证列表中出现新目录条目，且刷新页面后依然存在。

**Acceptance Scenarios**:

1. **Given** 用户位于根目录下的笔记管理页面，**When** 点击"新建目录"并输入名称"工作笔记"后确认，**Then** 根目录下新增一个名为"工作笔记"的目录条目。
2. **Given** 用户位于某个已存在目录"工作笔记"内部，**When** 点击"新建目录"并输入名称"周报"后确认，**Then** 新目录"周报"成为"工作笔记"的子目录，而不是根目录下的条目。
3. **Given** 根目录下已存在名为"工作笔记"的目录，**When** 用户在根目录下尝试新建同样名为"工作笔记"的目录，**Then** 系统阻止保存并提示名称已存在。
4. **Given** 根目录下已存在标题为"工作笔记"的笔记（非目录），**When** 用户在根目录下尝试新建名为"工作笔记"的目录，**Then** 系统同样阻止保存并提示名称冲突（目录与笔记的名称在同一层级下互斥）。

---

### User Story 2 - 以树形结构浏览目录与笔记 (Priority: P2)

用户希望在笔记管理页面以树形表格的方式浏览目录层级，通过点击目录条目最左侧的三角图标展开或收起其下级内容，而无需跳转页面；也可以点击目录条目本身，进入该目录对应的子级列表页面，专注查看某一层级的内容。

**Why this priority**: 创建目录后必须要有对应的浏览方式才能形成闭环，是目录能力发挥价值的关键场景，但依赖 User Story 1 已完成。

**Independent Test**: 可独立测试——预先创建包含多级子目录和笔记的数据，验证点击三角图标可原地展开/收起子级，点击目录名称可导航到对应子级列表页并在 URL 中携带目录 ID。

**Acceptance Scenarios**:

1. **Given** 树形表格中存在一个包含子级内容的目录条目，**When** 用户点击其最左侧的三角图标，**Then** 该目录的直接子级（子目录与子笔记）在原表格中展开显示，且三角图标变为展开态。
2. **Given** 目录条目已展开，**When** 用户再次点击三角图标，**Then** 其子级内容收起，恢复为折叠态。
3. **Given** 用户在树形表格中看到一个目录条目，**When** 用户点击该目录的名称（而非三角图标），**Then** 页面导航到仅显示该目录直接子级内容的列表页面，且 URL 中携带该目录 ID 的 Base58 编码值作为参数。
4. **Given** 用户展开一个没有任何子级内容的目录，**When** 展开完成，**Then** 系统在该目录下方显示"暂无内容"提示，而不是空白区域。

---

### User Story 3 - 图标与缩进的视觉层级 (Priority: P3)

用户希望通过图标快速区分目录与笔记，并在多级展开时通过整体缩进直观感受层级深度。

**Why this priority**: 属于体验优化，不影响核心功能是否可用，但显著提升树形浏览的可读性，优先级低于创建与浏览能力。

**Independent Test**: 可独立测试——创建至少三层嵌套的目录/笔记结构并全部展开，验证每一层的三角图标、类型图标与名称整体随层级缩进，且目录与笔记图标可视区分。

**Acceptance Scenarios**:

1. **Given** 列表中同时存在目录条目和笔记条目，**When** 页面渲染完成，**Then** 目录条目与笔记条目左侧显示不同的图标，图标尺寸与同行文字大小接近。
2. **Given** 一个三级嵌套目录结构（根 > A > B）全部展开，**When** 查看 B 目录下的笔记条目，**Then** 该笔记条目的三角占位、图标与名称作为一个整体，相对根层级有两级缩进，缩进层次与嵌套深度一致。

---

### Edge Cases

- 用户尝试在自己不拥有的目录下创建子目录或子笔记（例如构造他人目录的 ID 作为父级）时，系统必须拒绝并提示目录不存在或无权限。
- 用户输入的目录名称包含前后空白或为空字符串时，视为未填写，阻止保存。
- 同一层级下，目录与笔记的名称唯一性校验需忽略大小写差异吗——本次不做强制要求，按精确字符串匹配处理。
- 递归展开多级目录时，若某一层级子级数据量较大，仅在用户实际点击展开时才加载/渲染该层级，避免一次性渲染整棵树。
- 目录的重命名、移动、删除、批量操作均不在本次范围内，仅需保证创建能力可用且不破坏现有笔记的正常查看与编辑。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在笔记数据模型中新增 `mime_type` 字段：笔记类型条目固定为 `text/markdown`，目录类型条目固定为 `directory`。
- **FR-002**: 系统 MUST 在笔记数据模型中新增 `parent_id` 字段，用于表示该条目所属的父目录；`parent_id` 为空表示该条目位于根目录。
- **FR-003**: 系统 MUST 对已存在的历史笔记数据进行迁移，默认将 `mime_type` 设为 `text/markdown`，`parent_id` 设为空（根目录），且迁移过程不影响开发环境（本地 SQLite）与生产环境（Cloudflare D1）的数据一致性。
- **FR-004**: 用户 MUST 能在笔记管理页面（`/[lang]/console/notes`）的"新建笔记"按钮左侧看到"新建目录"入口。
- **FR-005**: 点击"新建目录"后，系统 MUST 弹出对话框，要求用户填写目录名称（必填）与描述信息（可选）。
- **FR-006**: 系统 MUST 在保存目录前，校验同一父级（相同 `parent_id`）范围内不存在同名的目录或笔记（名称唯一性校验覆盖目录与笔记两种类型），并且仅在当前用户自己的数据范围内校验。
- **FR-007**: 当名称与同层级下已有目录或笔记冲突时，系统 MUST 阻止保存并向用户展示明确的错误提示。
- **FR-008**: 系统 MUST 仅允许用户对自己拥有的笔记与目录执行创建、校验和展示操作，沿用现有按所属用户隔离数据的权限模型。
- **FR-009**: 系统 MUST 将 `/[lang]/console/notes` 笔记管理页面（即新建目录入口所在页面）本身改造为树形表格，用于展示目录与笔记的层级结构，无需新建独立页面。
- **FR-010**: 树形表格中，每个目录条目左侧 MUST 显示可点击的三角图标；点击后 MUST 在当前页面原地展开或收起其直接子级内容，不发生页面跳转。
- **FR-011**: 树形表格中，点击目录条目的名称（而非三角图标）时，系统 MUST 导航到仅展示该目录直接子级内容的列表页面。
- **FR-012**: 子级列表页面的 URL MUST 携带父目录 ID 作为参数，且该 ID 的展现格式 MUST 与现有笔记详情页 URL（如 `/en/console/notes/Cdc6ZFomke37Vz84fqNEm`）中笔记 ID 的 Base58 编码风格保持一致。
- **FR-013**: 树形表格中，目录条目与笔记条目左侧 MUST 分别显示与其类型对应的图标，图标尺寸 MUST 与同行文字大小接近，使用户无需阅读文字即可区分类型。
- **FR-014**: 当子级内容通过点击三角图标展开显示时，三角图标、类型图标与条目名称 MUST 作为一个整体，随层级深度一起整体缩进，而不是仅缩进三角图标本身。
- **FR-015**: 用户展开一个没有任何子级内容的目录时，系统 MUST 显示明确的"暂无内容"提示。

### Key Entities *(include if feature involves data)*

- **笔记条目（Note Item）**: 现有笔记记录的扩展概念，通过 `mime_type` 区分是"笔记"（`text/markdown`）还是"目录"（`directory`）；通过 `parent_id` 表达其所属的父目录，空值表示位于根目录。
- **目录（Directory）**: `mime_type` 为 `directory` 的笔记条目，具有名称（复用现有标题字段）与可选描述（复用现有正文字段），可以作为其他笔记条目或子目录的父级容器。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可以在 10 秒内完成一次目录创建操作（从点击入口到目录出现在列表中）。
- **SC-002**: 当用户尝试创建与同层级下已有目录/笔记同名的目录时，100% 的情况下会收到重名提示且不会产生重复条目。
- **SC-003**: 用户无需离开当前页面，即可通过点击三角图标查看任意目录下的直接子级内容。
- **SC-004**: 用户点击目录名称后能够进入对应子级列表页面，且该子级视图状态体现在页面 URL 中（刷新页面后仍停留在该子级视图）。
- **SC-005**: 在包含目录与笔记混合条目的列表中，90% 以上的用户能够仅凭图标在 1 秒内区分出目录与笔记类型的条目。

## Assumptions

- 目录名称复用笔记现有的标题字段，描述信息复用笔记现有的正文字段，不新增专门的"描述"字段。
- 本次范围仅包含"创建目录"能力；目录/笔记的重命名、移动、删除、批量操作均不在本次范围内。
- 目录类型条目不需要发布/审批状态；现有的发布状态、审批状态等字段对目录类型条目不生效或保持默认值，因为目录本身不是可发布内容。
- 名称唯一性校验仅在同一用户、同一 `parent_id` 范围内进行，不同用户之间允许重名，沿用现有按用户隔离数据的权限模型。
- 子级列表页面的父目录 ID 参数复用现有的 Base58 编码方案，无需新增编码方式。
- 树形表格的展开/收起状态仅作为前端交互状态，不需要持久化到服务端。
