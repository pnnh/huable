# Feature Specification: 笔记与频道的保存/发布分离及审核流程简化

**Feature Branch**: `[006-publish-approval-flow]`

**Created**: 2026-09-22

**Status**: Draft

**Input**: User description: "结合以上对话调整notes和channels的新增和编辑逻辑。这里需要明确区分"保存"和"发布"两个概念。仅仅新增或者编辑并保存并不会涉及审核事件。当把一个notes发布到某个频道，或channels设置为公开状态时，才会产生审核事件。为了简化notes和channels的编辑和发布流程，现在需要做以下调整：移除notes和channels表中的is_public字段，统一通过approval_status字段来跟踪发布和公开状态；当新增或编辑notes和channels后，approval_status字段统一变成『未发布状态』；在notes和channels的编辑页面（新增页面不需要）工具栏保存按钮旁边增加『发布』按钮，点击后approval_status字段变成挂起等待状态，直到admin角色审批后状态变成已审核状态，此时才可以在首页列表显示；如果当前用户已经是admin，则approval_status直接变成已审核状态，不创建待审核事件；批量上传notes时和一次单个新增note的逻辑一致，默认不关联频道，状态为未发布；当在note的编辑页面点击发布时需要弹窗选择频道，不再通过编辑页面直接设置频道；将/en/console/notes页面的设置频道和设置发布状态按钮合并成一个『批量发布』按钮，功能和发布单个笔记逻辑一致，点击后弹出频道选择下拉框，选择确认后修改笔记关联频道并设置发布状态。"

## Clarifications

### Session 2026-09-22

- Q: 笔记在公开页面（非 `/{lang}/console` 开头、未做统一用户身份校验的页面）的可见性，是否需要同时满足"笔记自身已审核"与"所属频道也已审核"两个条件？ → A: 是，两者必须同时为"已审核"才展示，缺一不可。
- Q: 频道的"发布"操作是否也需要像笔记一样弹出二次确认弹窗？ → A: 是，频道发布同样需要弹窗二次确认（无需像笔记那样选择目标频道，仅做确认/取消）。
- Q: 笔记与频道的编辑页面、控制台列表页面是否需要展示当前的审核发布状态标识？ → A: 需要，编辑页面与控制台列表页面均须显示当前状态（未发布/待审核/已审核/已拒绝）。
- Q: 管理员拒绝后，所有者再次编辑并保存内容时的最终状态，是否与既有 FR-016 所定义的"未发布"草稿状态一致（而非另一种独立的"未审核"状态）？ → A: 一致，统一使用"未发布"作为该状态的规范名称，可重新走"发布→审核"流程。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 保存与发布解耦 (Priority: P1)

用户在新增或编辑笔记/频道时，点击"保存"只会记录内容变更，不会触发任何审核动作；只有用户主动点击"发布"，内容才会进入审核流程或（管理员场景下）直接对外可见。

**Why this priority**: 这是本次改造的核心心智模型——把"内容编辑"和"提交公开"彻底拆开，其余所有规则（频道选择、批量发布、管理员免审）都建立在这个前提之上。

**Independent Test**: 新增一篇笔记只填写标题正文并点击"保存"，验证笔记状态为"未发布"且审核列表中没有出现任何相关待审核事项；随后编辑该笔记再次"保存"，验证状态仍为"未发布"，审核列表依旧无新增记录。

**Acceptance Scenarios**:

1. **Given** 用户在笔记/频道新增页面填写内容, **When** 用户点击"保存", **Then** 系统创建该笔记/频道且状态为"未发布"，不生成任何待审核事件。
2. **Given** 一篇状态为"未发布"的笔记/频道, **When** 用户修改内容并点击"保存", **Then** 状态保持"未发布"，不生成待审核事件。
3. **Given** 一篇状态为"已审核"（已公开）的笔记/频道, **When** 所有者编辑内容并点击"保存"（未点击发布）, **Then** 状态回退为"未发布"，该内容立即从面向公众的列表中隐藏，直至用户重新发布并通过审核。
4. **Given** 一篇笔记/频道存在尚未被管理员处理的待审核事件, **When** 所有者在管理员处理之前再次编辑内容并点击"保存"（未点击发布）, **Then** 该待审核事件被作废（标记为已处理，不再出现在管理员的待处理列表中），笔记/频道状态回退为"未发布"。

---

### User Story 2 - 笔记发布时选择频道 (Priority: P1)

用户在笔记编辑页面点击"发布"，系统弹出频道选择弹窗；用户确认目标频道后，笔记被关联到该频道并按角色规则进入"待审核"或直接"已审核"状态。编辑页面本身不再提供直接设置频道的入口。

**Why this priority**: 发布笔记必须绑定频道才有意义，这是笔记从草稿变为可审核/可见内容的唯一入口，直接决定审核流程能否正确触发。

**Independent Test**: 编辑一篇已保存的草稿笔记，点击"发布"，在弹窗中选择一个频道并确认，验证笔记的频道字段被更新，且（以非管理员身份操作时）在审核列表中出现一条对应的待审核事件。

**Acceptance Scenarios**:

1. **Given** 用户在笔记编辑页面（非新增页面）, **When** 用户查看工具栏, **Then** "发布"按钮显示在"保存"按钮旁边。
2. **Given** 用户在笔记新增页面, **When** 用户查看工具栏, **Then** 不显示"发布"按钮。
3. **Given** 用户点击"发布", **When** 弹窗展示可选频道列表, **Then** 用户必须选择一个频道才能确认发布；未选择频道时确认按钮不可用或给出提示。
4. **Given** 非管理员用户确认发布并选择了频道, **When** 提交完成, **Then** 笔记的频道字段被更新为所选频道，状态变为"待审核"，并生成一条新的待审核事件。
5. **Given** 管理员用户确认发布并选择了频道, **When** 提交完成, **Then** 笔记的频道字段被更新为所选频道，状态直接变为"已审核"，不生成待审核事件。
6. **Given** 一篇笔记自身状态为"已审核"但所属频道当前状态不是"已审核"（未发布/待审核/已拒绝）, **When** 访客查看公开页面, **Then** 该笔记不会出现在任何公开列表或详情页中。

---

### User Story 3 - 频道发布审核 (Priority: P2)

用户在频道编辑页面点击"发布"，频道按角色规则进入"待审核"或直接"已审核"状态，从而决定该频道是否对公众可见（是否为"公开频道"）。

**Why this priority**: 与笔记发布同等重要，但频道数量与编辑频率通常低于笔记，独立于 User Story 2 可单独验证。

**Independent Test**: 编辑一个已保存的草稿频道，点击"发布"，验证非管理员操作后频道状态变为"待审核"并生成待审核事件；管理员操作后状态直接变为"已审核"。

**Acceptance Scenarios**:

1. **Given** 用户在频道编辑页面（非新增页面）, **When** 用户查看工具栏, **Then** "发布"按钮显示在"保存"按钮旁边；新增页面不显示该按钮。
2. **Given** 用户点击频道的"发布"按钮, **When** 系统弹出二次确认弹窗, **Then** 用户必须点击确认后才真正提交发布；点击取消则不产生任何状态变化。
3. **Given** 非管理员用户确认发布, **When** 提交完成, **Then** 频道状态变为"待审核"，并生成一条待审核事件。
4. **Given** 管理员用户确认发布, **When** 提交完成, **Then** 频道状态直接变为"已审核"，不生成待审核事件。

---

### User Story 4 - 笔记列表批量发布 (Priority: P2)

用户在笔记控制台列表页勾选多篇笔记，点击合并后的"批量发布"入口，在弹出的频道选择框中确认目标频道后，系统为所有选中笔记统一设置该频道并按发布规则提交审核（或管理员直接通过）。

**Why this priority**: 是单篇发布（User Story 2）在多选场景下的效率延伸，复用同一套发布规则，可在单篇发布完成后独立交付。

**Independent Test**: 在笔记列表勾选 3 篇草稿笔记，点击"批量发布"，选择某频道并确认，验证这 3 篇笔记的频道与状态均按单篇发布规则更新，其余未勾选笔记不受影响。

**Acceptance Scenarios**:

1. **Given** 笔记列表页原有的"设置频道"与"设置发布状态"两个按钮, **When** 用户查看工具栏, **Then** 两者已合并为一个"批量发布"按钮。
2. **Given** 用户未勾选任何笔记, **When** 用户查看工具栏, **Then** "批量发布"按钮处于禁用状态。
3. **Given** 用户已勾选若干笔记, **When** 用户点击"批量发布"并在弹窗中选择频道后确认, **Then** 所有选中笔记的频道字段被更新为该频道，并按发布规则（非管理员→待审核+生成事件；管理员→已审核+不生成事件）设置状态。
4. **Given** 批量发布操作已提交, **When** 操作完成, **Then** 未被勾选的笔记的频道与状态保持不变。

---

### User Story 5 - 批量上传笔记保持草稿态 (Priority: P3)

通过批量上传 Markdown 文件创建的笔记，必须与手动新增单篇笔记保持一致的默认行为：不关联任何频道，状态为"未发布"，不产生任何审核事件。

**Why this priority**: 用于保证既有的批量上传能力在本次审核流程改造后行为不发生退化，属于回归性验证，不引入新交互。

**Independent Test**: 通过批量上传创建若干篇笔记，验证每篇笔记的频道字段为空、状态为"未发布"，审核列表中没有出现与这些笔记相关的记录。

**Acceptance Scenarios**:

1. **Given** 用户通过批量上传成功创建笔记, **When** 查看新创建的笔记, **Then** 每篇笔记的频道字段为空，状态为"未发布"。
2. **Given** 批量上传已完成, **When** 查看审核列表, **Then** 没有因本次上传产生的待审核事件。

---

### User Story 6 - 拒绝后重新编辑发布 (Priority: P2)

管理员拒绝一条待审核事件后，对应笔记/频道进入独立的"已拒绝"状态；所有者可在编辑页面看到拒绝标记，编辑内容并点击"保存"后状态转为"未发布"，之后可像草稿一样重新点击"发布"提交审核。

**Why this priority**: 补全审核流程的闭环——没有这一步，被拒绝的内容将无法再次被所有者修改后重新提交，审核机制就不完整。

**Independent Test**: 管理员对一条待审核事件点击"拒绝"，验证对应笔记/频道状态变为"已拒绝"且不再出现在公开列表；所有者编辑该内容并点击"保存"，验证状态变为"未发布"；所有者再次点击"发布"，验证可重新生成新的待审核事件。

**Acceptance Scenarios**:

1. **Given** 一条待审核事件, **When** 管理员点击"拒绝", **Then** 对应笔记/频道状态变为"已拒绝"，不出现在面向公众的列表中。
2. **Given** 一篇状态为"已拒绝"的笔记/频道, **When** 所有者打开编辑页面, **Then** 页面展示该内容当前处于"已拒绝"状态。
3. **Given** 一篇状态为"已拒绝"的笔记/频道, **When** 所有者编辑内容并点击"保存", **Then** 状态变为"未发布"，所有者可像新草稿一样重新点击"发布"。

---

### User Story 7 - 查看审核发布状态标识 (Priority: P3)

用户在笔记/频道的编辑页面，以及控制台的笔记/频道列表页面，都能看到一个清晰的状态标识，反映该内容当前处于"未发布"、"待审核"、"已审核"或"已拒绝"中的哪一种状态。

**Why this priority**: 状态可见性是保存/发布分离模型能被用户正确理解和使用的前提，但不影响状态本身的流转逻辑，可在核心流程（User Story 1–4、6）交付后独立补充。

**Independent Test**: 分别将一篇笔记置于四种状态之一，打开其编辑页面与所在的控制台列表页面，验证两处展示的状态标识与该笔记的实际 approval_status 一致；对频道重复同样验证。

**Acceptance Scenarios**:

1. **Given** 一篇笔记/频道处于"未发布"/"待审核"/"已审核"/"已拒绝"中的任一状态, **When** 所有者打开其编辑页面, **Then** 页面上展示与当前状态一致的标识。
2. **Given** 控制台的笔记列表页面或频道列表页面, **When** 用户查看列表, **Then** 每一行都展示对应笔记/频道当前的状态标识。

---

### Edge Cases

- 用户在笔记编辑页面点击"发布"但未在弹窗中选择任何频道就尝试确认：系统必须阻止提交并提示需要选择频道。
- 用户点击"批量发布"但未勾选任何笔记：入口不可用。
- 用户点击"批量发布"但未在弹窗中选择频道：系统必须阻止提交并提示需要选择频道。
- 一篇笔记当前已经是"待审核"状态，所有者在管理员处理之前再次编辑并点击"保存"（未点击发布）：该待审核事件被作废，笔记状态回退为"未发布"（见 User Story 1 场景 4）。
- 管理员对一条待审核事件执行"拒绝"：内容状态变为独立的"已拒绝"状态，所有者编辑并保存后转为"未发布"方可重新发布（见 User Story 6）。
- 频道被编辑保存后从"已审核"回退为"未发布"（或被拒绝变为"已拒绝"）：即使其下的笔记自身仍为"已审核"状态，这些笔记也会立即从公开页面隐藏，因为公开可见性要求笔记自身与所属频道同时为"已审核"（见 FR-007、FR-018）。
- 用户点击频道"发布"确认弹窗中的"取消"：系统不得修改频道的审核状态，也不得生成待审核事件。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须将笔记与频道的"是否公开/是否发布"状态统一收敛为单一的审核状态字段，不再使用独立的布尔型"是否公开"字段。
- **FR-002**: 系统必须在用户新增笔记或频道并点击"保存"后，将其状态设置为"未发布"，且不生成任何待审核事件。
- **FR-003**: 系统必须在用户编辑已有笔记或频道并点击"保存"（未点击"发布"）后，将其状态设置为"未发布"，且不生成任何待审核事件；若编辑前状态为"已审核"，编辑保存后必须立即从面向公众的列表中隐藏。
- **FR-004**: 系统必须仅在用户主动点击"发布"时才可能生成待审核事件。
- **FR-005**: 当非管理员用户点击"发布"时，系统必须将对应笔记或频道的状态设置为"待审核"，并生成一条待审核事件供管理员处理。
- **FR-006**: 当管理员用户点击"发布"时，系统必须将对应笔记或频道的状态直接设置为"已审核"，且不生成待审核事件。
- **FR-007**: 系统必须仅在满足以下条件时才在公开页面（`/{lang}/console` 开头以外、不做统一用户身份校验的页面，例如首页、频道列表、频道详情、笔记详情）展示对应内容：频道必须自身状态为"已审核"；笔记必须自身状态为"已审核"且其所属频道状态也为"已审核"，两者缺一不可。
- **FR-008**: 笔记编辑页面（非新增页面）必须在"保存"按钮旁提供"发布"按钮；新增页面不得显示该按钮。
- **FR-009**: 频道编辑页面（非新增页面）必须在"保存"按钮旁提供"发布"按钮；新增页面不得显示该按钮。
- **FR-010**: 点击笔记的"发布"按钮时，系统必须弹出频道选择弹窗，用户确认目标频道后才提交发布；笔记编辑页面本身不再提供直接设置频道的入口。
- **FR-011**: 通过批量上传创建的笔记，必须与单篇新增笔记保持一致的默认行为——不关联任何频道，状态为"未发布"，不生成待审核事件。
- **FR-012**: 笔记控制台列表页面必须将原有的"设置频道"与"设置发布状态"两个入口合并为一个"批量发布"入口。
- **FR-013**: 点击"批量发布"必须弹出频道选择弹窗；用户确认频道后，系统必须为所有选中的笔记统一设置该频道，并按 FR-005/FR-006 的规则设置审核状态。
- **FR-014**: 批量发布操作必须仅作用于用户当前勾选的笔记，不得影响未勾选笔记的频道字段与审核状态。
- **FR-015**: 当管理员对一条待审核事件执行"拒绝"时，系统必须将对应笔记/频道的状态设置为独立的"已拒绝"状态（不同于"未发布"），并且该状态下的内容不得出现在面向公众的列表中。
- **FR-016**: 系统必须在笔记/频道编辑页面向所有者展示当前处于"已拒绝"状态的标记；所有者编辑内容并点击"保存"后，系统必须将状态由"已拒绝"变为"未发布"，允许所有者像新草稿一样重新点击"发布"提交审核。
- **FR-017**: 若笔记/频道存在一条尚未被管理员处理的待审核事件，所有者在管理员处理之前再次编辑并点击"保存"（未点击发布），系统必须将该待审核事件作废（标记为已处理，不再出现在管理员的待处理列表中），并将对应笔记/频道状态回退为"未发布"。
- **FR-018**: 系统必须在公开页面的数据查询层面强制执行 FR-007 的可见性过滤，而不是仅在前端界面隐藏；处于"未发布"、"待审核"、"已拒绝"状态的笔记/频道，以及所属频道未同时满足"已审核"条件的笔记，在任何情况下都不得通过公开页面的接口或渲染结果泄露。
- **FR-019**: 频道编辑页面点击"发布"按钮时，系统必须弹出二次确认弹窗；用户点击确认后才提交发布并按 FR-005/FR-006 设置状态，点击取消则不产生任何变化。
- **FR-020**: 笔记编辑页面与控制台笔记列表页面必须展示笔记当前的审核发布状态标识（未发布 / 待审核 / 已审核 / 已拒绝）。
- **FR-021**: 频道编辑页面与控制台频道列表页面必须展示频道当前的审核发布状态标识（未发布 / 待审核 / 已审核 / 已拒绝）。

### Key Entities *(include if feature involves data)*

- **笔记（Note）**：用户创建的内容单元，拥有标题、正文、所属父级目录、（可选）所属频道，以及统一的审核状态（未发布 / 待审核 / 已审核 / 已拒绝）。
- **频道（Channel）**：笔记的公开归属分组，拥有名称、描述，以及统一的审核状态（未发布 / 待审核 / 已审核 / 已拒绝），仅"已审核"状态的频道被视为对公众公开。
- **待审核事件（Approval Event）**：由用户点击"发布"触发的审核请求记录，关联具体笔记或频道，记录处理结果（通过/拒绝）及处理人，仅在非管理员发起发布时创建；当所有者在事件处理前再次保存内容时，该事件会被作废。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 普通用户可以任意次数保存笔记/频道草稿，全程不出现在管理员的待审核列表中，直到用户主动点击一次"发布"。
- **SC-002**: 管理员点击"发布"后，笔记或频道在同一次操作内即对公众可见，无需等待其他管理员审核。
- **SC-003**: 非管理员用户发布的内容，在对应待审核事件被批准前，100% 不出现在面向公众的列表中。
- **SC-004**: 用户可以在一次批量发布操作中为最多 200 篇笔记完成"关联频道 + 提交发布"，无需逐篇打开编辑页面。
- **SC-005**: 通过批量上传创建的笔记，100% 以"未发布"状态创建，不会意外出现在审核列表或公开列表中。
- **SC-006**: 只要笔记自身或其所属频道有任意一方未处于"已审核"状态，该笔记 100% 不会出现在任何公开页面中。

## Assumptions

- "公开页面"/"面向公众的列表"特指 `/{lang}/console` 开头以外、不做统一用户身份校验的页面（首页、频道列表/详情、笔记详情等）；用户自己的控制台笔记/频道列表仍展示其全部状态（未发布/待审核/已审核/已拒绝）的内容，不受本次改造影响。
- 频道的"发布"确认弹窗仅为单一的确认/取消动作，不需要像笔记那样弹出频道选择弹窗（频道本身没有可选的从属对象）。
- 现有"待审核事件"记录结构（关联笔记/频道、处理人、处理结果、处理时间）保持不变，仅调整触发时机（由"新增/编辑保存"改为仅"点击发布"触发）以及审核状态的取值范围（由二态"待审核/已审核"扩展为四态"未发布/待审核/已审核/已拒绝"）。
- "未审核"与"未发布"指代同一种状态，规格中统一使用"未发布"作为规范名称。
- 批量发布沿用现有批量操作的数量上限（一次最多 200 篇笔记）。
- 管理员在"批量发布"场景下同样适用免审核规则：管理员批量发布的笔记直接变为"已审核"，不生成待审核事件，与单篇发布规则一致。
- 数据库层面移除 `is_public`（频道）与现状 `is_published`（笔记）等旧布尔字段、扩展 `approval_status` 取值范围等属于技术实现细节，将在后续 `/speckit-plan` 阶段设计，不在本规格中展开。
