# Feature Specification: 笔记批量设置频道与发布状态

**Feature Branch**: `005-notes-batch-actions`

**Created**: 2026-09-22

**Status**: Draft

**Input**: User description: "在/en/console/notes页面工具栏增加"设置频道"和"设置发布状态"按钮，然后在下方列表每一行最左侧和表头增加复选框。允许批量选中笔记，设置频道和公开状态。注意仅可以选中笔记不可选中目录。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 批量设置笔记所属频道 (Priority: P1)

用户在笔记列表中勾选多篇笔记，点击工具栏的"设置频道"按钮，从自己拥有的频道中选择一个目标频道（或选择"无频道"），一次性将所有选中笔记归属到该频道。

**Why this priority**: 这是本功能最核心的价值——避免用户逐条打开笔记编辑频道，是明确要解决的效率问题。

**Independent Test**: 勾选 3 篇笔记，点击"设置频道"，选择某个频道并确认，验证这 3 篇笔记的频道均已更新，其余未勾选笔记不受影响。

**Acceptance Scenarios**:

1. **Given** 列表中存在多篇笔记且用户拥有至少一个频道, **When** 用户勾选若干笔记并通过"设置频道"选择某频道确认, **Then** 所有被选中笔记的频道被更新为该频道，列表随即刷新显示新的频道名称。
2. **Given** 用户已勾选若干笔记, **When** 用户在"设置频道"弹窗中选择"无频道"并确认, **Then** 所有被选中笔记的频道被清空。
3. **Given** 用户未勾选任何笔记, **When** 用户查看工具栏, **Then** "设置频道"按钮处于禁用状态，无法点击。

---

### User Story 2 - 批量设置笔记发布状态 (Priority: P2)

用户勾选多篇笔记，点击工具栏的"设置发布状态"按钮，选择"已发布"或"草稿"，一次性更新所有选中笔记的发布状态。

**Why this priority**: 与批量设置频道同等重要的效率诉求，但相对独立，可在频道功能之后交付。

**Independent Test**: 勾选若干笔记，通过"设置发布状态"将其批量设为"已发布"，验证列表中对应笔记状态标签变为已发布，且未选中笔记状态不变。

**Acceptance Scenarios**:

1. **Given** 用户已勾选若干笔记, **When** 用户通过"设置发布状态"选择"已发布"并确认, **Then** 所有选中笔记的发布状态被更新为已发布，列表刷新显示新状态。
2. **Given** 用户已勾选若干笔记, **When** 用户通过"设置发布状态"选择"草稿"并确认, **Then** 所有选中笔记的发布状态被更新为草稿。
3. **Given** 用户未勾选任何笔记, **When** 用户查看工具栏, **Then** "设置发布状态"按钮处于禁用状态。

---

### User Story 3 - 通过复选框勾选与全选笔记 (Priority: P1)

用户在列表每一行最左侧看到复选框用于勾选单篇笔记，在表头看到复选框用于一键全选/取消全选当前视图下的所有笔记；目录行不显示复选框，无法被勾选。

**Why this priority**: 这是批量操作的入口，User Story 1、2 都依赖它，属于同等优先级的基础能力。

**Independent Test**: 打开笔记列表，验证目录行左侧无复选框，笔记行左侧有复选框；点击表头复选框，验证当前视图下所有笔记行被勾选，目录行不受影响；再次点击表头复选框，验证全部取消勾选。

**Acceptance Scenarios**:

1. **Given** 列表中同时存在目录和笔记, **When** 用户查看每一行, **Then** 目录行最左侧不显示复选框，笔记行最左侧显示可勾选的复选框。
2. **Given** 列表中存在多篇笔记, **When** 用户点击表头复选框, **Then** 当前视图下所有笔记行被勾选，目录行保持不受影响。
3. **Given** 当前视图下所有笔记已被勾选, **When** 用户再次点击表头复选框, **Then** 所有笔记的勾选被取消。
4. **Given** 用户手动勾选了当前视图下的全部笔记, **When** 用户查看表头复选框, **Then** 表头复选框自动呈现为"已全选"状态。

---

### Edge Cases

- 用户展开某个目录查看其子笔记后再折叠该目录：已勾选的子笔记选中状态应被清除（子笔记不在当前可见列表中，不计入后续批量操作）。
- 用户勾选笔记后离开当前目录层级（点击进入其他目录）：之前的勾选状态被清除。
- 批量设置频道或发布状态提交后，服务器返回部分失败（例如某篇笔记已被删除或不再属于当前用户）：系统需提示用户哪些笔记更新失败，并保留成功更新的结果。
- 用户在没有任何自建频道的情况下点击"设置频道"：弹窗需提示当前没有可选频道，并引导用户先创建频道。
- 批量操作提交后但服务器响应尚未返回期间：工具栏按钮与复选框应禁用，避免重复提交。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在 /console/notes 页面工具栏中，"新建目录""上传笔记""新建笔记"按钮旁增加"设置频道"和"设置发布状态"两个按钮。
- **FR-002**: 系统必须在笔记列表每一行最左侧和表头新增复选框列。
- **FR-003**: 系统必须仅对类型为笔记（非目录）的行渲染可勾选的复选框；目录行不得显示或提供复选框。
- **FR-004**: 用户必须能够通过点击表头复选框，一键勾选或取消勾选当前视图下的所有笔记行（不含目录）。
- **FR-005**: 表头复选框的勾选状态必须准确反映当前视图下笔记行的整体勾选情况（全部勾选/部分勾选/未勾选）。
- **FR-006**: 当没有任何笔记被勾选时，"设置频道"和"设置发布状态"按钮必须处于禁用状态。
- **FR-007**: 点击"设置频道"按钮必须弹出频道选择界面，列出当前用户拥有的全部频道以及"无频道"选项，供用户选择一个目标应用到所有已勾选笔记。
- **FR-008**: 点击"设置发布状态"按钮必须弹出状态选择界面，供用户在"已发布"与"草稿"之间选择一个目标状态应用到所有已勾选笔记。
- **FR-009**: 确认批量设置后，系统必须仅更新当前用户拥有、且已被勾选的笔记，不得影响未勾选的笔记或任何目录。
- **FR-010**: 批量设置完成后，系统必须刷新列表以展示每篇笔记最新的频道和发布状态，并清空当前的勾选状态。
- **FR-011**: 批量设置提交后，系统必须向用户反馈操作结果（成功、失败或部分失败及原因）。
- **FR-012**: 系统必须校验所有被批量操作的笔记均归属于当前登录用户，拒绝对非本人笔记的更新请求。

### Key Entities

- **笔记 (Note)**: 用户创建的内容条目，具有标题、所属目录、所属频道（可为空）、发布状态（已发布/草稿）等属性；是本功能可被勾选和批量修改的对象。
- **目录 (Directory)**: 用于组织笔记的容器条目，本身不具备频道或发布状态属性，不参与勾选和批量操作。
- **频道 (Channel)**: 用户拥有的发布渠道，笔记可归属于某个频道或不归属任何频道；批量设置频道时从用户已有频道中选择。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在 30 秒内完成对 10 篇笔记的批量频道设置（从勾选到看到列表更新完成）。
- **SC-002**: 批量操作 100% 只影响用户实际勾选的笔记，不会变更任何目录或未勾选笔记的数据。
- **SC-003**: 相比逐条编辑笔记设置频道或发布状态，批量设置 10 篇笔记所需的操作步骤减少 80% 以上。
- **SC-004**: 在正常网络条件下，批量设置操作的成功率不低于 99%。

## Assumptions

- 目录不具备频道和发布状态属性，因此在本功能中始终不可勾选、不参与批量操作，这与用户明确说明一致。
- 表头复选框的"全选"范围限定在当前视图下已加载展示的笔记行；用户折叠或切换目录层级后，先前的勾选状态会被清除，不做跨层级、跨页面的持久化勾选。
- "设置频道"弹窗允许选择"无频道"选项，用于批量清空所选笔记的频道归属，行为与现有单篇笔记编辑页面保持一致。
- 批量将笔记设置为"已发布"并关联频道时，沿用现有系统规则：该笔记进入待审批状态，而非立即公开可见；批量操作不绕过既有审批流程。
- 批量操作为同步一次性提交，不提供撤销功能；如需更改可再次执行批量设置或逐条编辑。
